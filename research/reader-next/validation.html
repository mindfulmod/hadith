Source integrity

  • All 24 rendered English/Arabic blocks matched the canonical record exactly: three concepts × two hadith × two English and two Arabic blocks.
  • Collapsed chains remain complete in the DOM and expand on request.
  • The existing source checker passes both Arabic hashes and complete entry equality.
  • No wording, source records, audio files or narrator scripts were edited.

Interactions and responsive layouts

  • Source sheets open with the correct hadith, Arabic, named comparisons and licensing. Closing restores focus to the source control. Escape dismisses the native dialog.
  • Bookmark toggling, Hadith 1 → 2, the session ending and separate prototype state were exercised.
  • All three reading layouts were checked at 320px with 28px text in night mode: no horizontal overflow. The comparison uses standard 21px text independently of prototype preferences.
  • The companion's wider layout was inspected at 1024px, including the reference rail. Day/night entry and reading states were visually reviewed.
  • With byte-range-capable local delivery, the continuous recording crossed into Hadith 2; source access showed Hadith 2, and switching to its reading view retained playback. Pause and close controls worked. Initial seeking on a generic development server failed because it lacked byte-range delivery; the test server was corrected to match production-style delivery.
  • The reference catalogue's counts and study relationships are checked by check-study.mjs; the ledger discloses excluded candidates.

Colour

Existing reader button labels: copper day action 5.60:1, apricot night action 7.01:1. Hover states: 7.35:1 and 8.98:1. Concept buttons use a slightly darker night label, giving 7.93:1. These are calculated sRGB contrast ratios, not a complete accessibility certification.

Regression checks

The release builder, canonical content checker and all eight existing tests pass. They cover media ranges, complete-hadith session boundaries, audio chapter mapping, offline file integrity, saved-state migration, release hashes and narration-script equality. The production reader's offline controller and playback implementation are unchanged.

What this does not establish

These are online layout experiments, not an offline release of a new reader shell. No new iPhone locked-screen test, comprehensive assistive-technology audit, longitudinal reading study or independent scholarly review was completed in this design pass. The user's prior successful iPhone offline test applies to the existing reader's continuous two-hadith recording.

The research ledger records public-page and documentation observations. Five limited browser samples are not full audits of those products. The recommendation remains a design hypothesis for the user's next comparison.
